# System Requirements — ระบบบริหารการซ่อมบำรุงด้วย AI (AI-Assisted Helpdesk Ticket System)

> เอกสารความต้องการของระบบ ประกอบการติดตามความก้าวหน้าโครงงาน
> สอดคล้องกับขอบเขตการวิจัยที่นำเสนอต่ออาจารย์ที่ปรึกษา

## 1. ภาพรวมระบบ

ระบบแจ้งปัญหาและแจ้งซ่อมออนไลน์ที่ใช้ AI (Vision LLM) วิเคราะห์ภาพถ่ายปัญหา
เพื่อลดขั้นตอนการแจ้งจาก 8 ขั้นตอน เหลือ 1–2 ขั้นตอน: **ถ่ายรูป → AI วิเคราะห์ → สร้าง Ticket อัตโนมัติ**

- **กลุ่มเป้าหมาย**: นักศึกษาและบุคลากรในมหาวิทยาลัย
- **ประเภทปัญหา**: งานซ่อมบำรุง อุปกรณ์ สาธารณูปโภค
- **ช่องทาง**: Web App (รองรับมือถือเต็มรูปแบบ) — LINE Official Account เป็นช่องทางเสริมใน Phase ถัดไป

## 3. Non-Functional Requirements

| รหัส | ความต้องการ | แนวทาง |
|---|---|---|
| NFR-01 | ใช้ได้ทุกอุปกรณ์ (มือถือ/แท็บเล็ต/คอม) ขนาดไม่เพี้ยน | Responsive design (Tailwind CSS), ทดสอบ mobile-first |
| NFR-02 | ฟอนต์ภาษาไทยแสดงผลถูกต้องทุกแพลตฟอร์ม | IBM Plex Sans Thai + fallback (Noto Sans Thai, Leelawadee UI, Thonburi) |
| NFR-03 | ความปลอดภัยข้อมูล: คนทั่วไปแจ้งได้แต่อ่านข้อมูลคนอื่นไม่ได้ | Row Level Security ทุกตาราง, รูปเก็บ private bucket + signed URL |
| NFR-04 | AI ล่มต้องไม่ทำให้ระบบรับแจ้งไม่ได้ | Best-effort analysis, fallback เป็นให้เจ้าหน้าที่จัดหมวดเอง |
| NFR-05 | เวลาแจ้งปัญหา ≤ 1–2 นาที (เดิม 10–15 นาที) | ฟอร์ม 3 ช่อง + AI กรอกส่วนที่เหลือ |
| NFR-06 | ระบบเริ่มใช้ได้โดยไม่มีค่าใช้จ่าย | Supabase/Vercel free tier |

## 4. หมวดหมู่และค่าคงที่ของระบบ

**ประเภทงานซ่อม** (ตรงกับระบบเดิมของหน่วยงาน 1:1 เพื่อย้ายข้อมูลเก่าได้):
1. งานซ่อมแซมครุภัณฑ์สุขาภิบาล (ประปา ท่อ สุขภัณฑ์)
2. งานซ่อมแซมครุภัณฑ์ไฟฟ้า
3. งานซ่อมแซมเครื่องปรับอากาศ
4. งานซ่อมแซมอาคาร
5. งานซ่อมแซมครุภัณฑ์สำนักงาน

**ระดับความเร่งด่วน**: `critical` วิกฤต (อันตราย/กระทบวงกว้าง) · `high` ด่วน (ใช้งานไม่ได้) · `medium` ปานกลาง · `low` ไม่เร่งด่วน

**สถานะงาน**: `pending` รอดำเนินการ · `in_progress` กำลังซ่อม · `done` เสร็จแล้ว · `cannot_proceed` ดำเนินการไม่ได้

## 5. สถาปัตยกรรม

```
ผู้แจ้ง (มือถือ/คอม)
   │  ถ่ายรูป + เลือกอาคาร/ห้อง
   ▼
Next.js Web App (Server Actions)
   │  รูป → Vision LLM API (วิเคราะห์อุปกรณ์/อาการ/หมวด/ความเร่งด่วน)
   ▼
Supabase (PostgreSQL + Auth + Storage + Realtime)
   │  realtime broadcast
   ▼
Dashboard เจ้าหน้าที่ (Kanban / Timeline / Heatmap / รายงาน)
```

ฐานข้อมูล 6 ตาราง: `buildings`, `rooms`, `service_types`, `staff`, `reports`, `report_status_history` (+ trigger บันทึกประวัติสถานะอัตโนมัติ)
