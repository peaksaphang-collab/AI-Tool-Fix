# UX/UI Design — ระบบบริหารการซ่อมบำรุงด้วย AI

## หลักการออกแบบ: Less is More

Pain point หลักของระบบเดิมคือ "กรอกเยอะ 8+ ขั้นตอน" — ทุกหน้าจอจึงออกแบบจากคำถามเดียว:
**"ตัดอะไรออกได้อีก โดยที่งานยังเสร็จ"**

| หลักการ | การนำไปใช้จริง |
|---|---|
| ขั้นตอนน้อยที่สุด | ฟอร์มแจ้งซ่อมเหลือ 3 จุดสัมผัส: รูป → อาคาร → ห้อง (ที่เหลือ AI + ไม่บังคับ) |
| Mobile-first | ปุ่มถ่ายรูปเปิดกล้องหลังทันที (`capture="environment"`), ทุกหน้า responsive |
| เห็นทุกอย่างหน้าเดียว | แดชบอร์ดไม่มี drill-down บังคับ — สถานะทุกงานอยู่ใน viewport เดียว แบ่ง 2 ฝั่งชัดเจน |
| สีสื่อความหมายเดียว | เหลือง=รอ น้ำเงิน=กำลังซ่อม เขียว=เสร็จ แดง=วิกฤต/ดำเนินการไม่ได้ — ใช้เหมือนกันทุกหน้า |
| ไม่มีของตกแต่งไร้หน้าที่ | ไม่ใช้อิโมจิ/ไอคอนประดับใน UI, ทุกอย่างที่ hover ได้ต้องกดได้จริง |

## Design System

- **ฟอนต์**: IBM Plex Sans Thai (โหลดผ่าน next/font พร้อม subset ไทย+ลาติน) — fallback: Noto Sans Thai, Leelawadee UI (Windows), Thonburi (macOS/iOS) → อ่านได้ถูกต้องทุกแพลตฟอร์มแม้โหลดฟอนต์หลักไม่สำเร็จ
- **Component Library**: shadcn/ui (Base UI) — ปุ่ม/ฟอร์ม/แท็บ/dialog มาตรฐานเดียวกันทั้งแอป รองรับคีย์บอร์ดและ screen reader
- **Layout**: Tailwind CSS, mobile-first breakpoints (`sm` 640 / `md` 768 / `lg` 1024)
- **แจ้งเตือน**: Sonner toast มุมบนกลาง — เด้งเมื่อมีเคสใหม่แบบเรียลไทม์

## โครงหน้าจอ (Screen Map)

```
/                หน้าแรก — 2 ปุ่มใหญ่: แจ้งซ่อม | เข้าสู่ระบบเจ้าหน้าที่
/report          ฟอร์มแจ้งซ่อม (สาธารณะ, mobile-first, จบใน 30 วิ)
/login           เข้าสู่ระบบเจ้าหน้าที่
/dashboard       บอร์ดสถานะ 2 ฝั่ง (ยังไม่เสร็จ | จบงานแล้ว) + realtime + toast
/dashboard/analytics  KPI · สรุปวัน/เดือน/ปี · รายงานประเภท/รายคน · Kanban · Timeline · Heatmap · ปฏิทิน
```

## รายละเอียดต่อหน้า

### หน้าแจ้งซ่อม `/report`
- พื้นที่ถ่ายรูปใหญ่เต็มความกว้าง (อัตราส่วน 16:9) + พรีวิวรูปทันทีที่เลือก
- ห้องจะเลือกได้หลังเลือกอาคารแล้วเท่านั้น (ตัวเลือกกรองตามอาคาร — กันเลือกผิด)
- ประเภทงาน: "ไม่เลือกก็ได้ — AI วิเคราะห์ให้อัตโนมัติ" (ลดภาระแต่เปิดทางคุมเอง)
- สำเร็จแล้วเห็นเครื่องหมายถูกสีเขียว + ปุ่มแจ้งรายการใหม่

### แดชบอร์ด `/dashboard`
- การ์ดงาน: รูปย่อ (signed URL หมดอายุใน 1 ชม.) + อาคาร·ห้อง + ผล AI + ป้ายความเร่งด่วน 4 สี
- งานฝั่ง "ยังไม่เสร็จ" เรียง วิกฤต → ด่วน → ปานกลาง → ไม่เร่งด่วน → ใหม่สุดก่อน
- ปุ่มตามบริบทสถานะ: รอ→[เริ่มซ่อม][เสร็จ][ดำเนินการไม่ได้], จบแล้ว→[เปิดงานใหม่]
- มอบหมายผู้รับผิดชอบ inline บนการ์ด ไม่ต้องเปิดหน้าใหม่

### หน้าสรุป `/dashboard/analytics`
- ไม่ใช้กราฟวงกลม/แท่ง (ข้อกำหนดจากผู้ใช้ระบบเดิม) — แทนด้วย KPI tiles, แถบสัดส่วนแนวนอน, heatmap ความเข้มสี, progress ring
- Kanban ลากได้จริง: `activationConstraint 5px` กันลากโดยไม่ตั้งใจบนมือถือ

## Accessibility & ความทนทาน

- ทุก input มี `<Label htmlFor>` จับคู่จริง, ปุ่มทุกปุ่มมีข้อความ (ไม่มีปุ่มไอคอนเปล่า)
- แสดงสถานะด้วย **ข้อความ+สี** เสมอ (ไม่พึ่งสีอย่างเดียว — รองรับตาบอดสี)
- ระบบยังทำงานเมื่อ: AI ล่ม (รับแจ้งต่อ), env ไม่ครบ (ขึ้นหน้าแนะนำแทน crash), รูปโหลดช้า (โครงหน้าไม่กระโดด)
